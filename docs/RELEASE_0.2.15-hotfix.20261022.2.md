# 0.2.15 · 10月22日第二次热修预览：奖励弹窗图片识别

修复已到主菜单却继续自动领奖、领奖弹窗出现后识别反复而卡住的问题。程序内部版本仍为 0.2.15，热修标识 reward_input_navigation_20261022。

## 本次修复

- 继续使用现有内嵌 CPU 小模型和 55 张共用参考图，不增加模型权重、下载或独立服务。
- 每日任务、通行证及通用返回导航共用奖励弹窗图片识别：同时核对 REWARD 标题、底部返回提示和蓝色横带。已确认的弹窗不再依赖 OCR 读出某一句中文。
- 奖励弹窗关闭改用 SendInput 明确发送虚拟桌面绝对移动、按下、松开；记录系统接收数量，点击后不立即移回光标。只用于弹窗关闭，领取与消费仍沿用原输入路径；释放失败仅补松开并停止。此输入修正尚待实机关闭验证。
- “进入主菜单”连续两帧确认主页后立即结束并推进队列，不再附带任务核对、奖励恢复或顺手领奖。日常领奖由用户选择的相应模块执行。
- 保留头像、昵称与战力区域排除、内存帧与 OCR 缓存、停止/F8、鼠标移动、窗口几何、前景与换日检查。原停止队列、pending 和已完成消费不改写；不自动重跑。

## 验证范围

本次 133 项离线检查通过：14 项保存画面与控制器检查、17 项队列继续检查、7 项队列策略、38 项返回导航回归、39 项游戏日保护、18 项模拟原生输入与路由检查。保存画面检查包括两个实际卡住的弹窗画面、一个领奖前页面及合成反例，不能把 14 项称为 14 个独立实机样本。另核对既有 55 张参考图，无其他页面误命中。

最终冻结程序自检、每日任务与通行证四次保存画面只读 worker 通过。原安装正常权限入口对当前实时奖励弹窗的一次只读捕获识别成功，OCR 缓存项为 0，actions=[]，无普通 PNG 落盘。此检查未关闭弹窗、未执行领奖或恢复 pending，也未运行整轮队列。随后经授权准备单次关闭验证时，窗口已是普通每日任务页，探针未发输入；新 SendInput 路径的真实关闭效果、实时导航及后续日常仍待用户调试。

## 下载与升级

首次使用解压完整 Portable 目录，运行 BD2Assistant.exe；默认只读。已有安装先关闭助手并备份原目录，再更新程序文件，保留原 config、runtime、evidence，不用默认配置覆盖自己的设置。使用正常权限的安装入口，不从带 Low 完整性标签的缓存目录运行。
